## #175
- Library mode: the only thing that can *close* a details is a script (no `name`, click
  intercepted, find-in-page only opens). So the issue's scenario needs a consumer DOM write.
- Issue's candidate rule == "compare with intended only". Breaks: commit writes `open`, click
  handled before the commit's `toggle` task, intended flips, echo read as platform change.
- Chosen: "known value" per element (last written or read). Checked cases: normal commit;
  script close + find reopen during pending close; click race; write + platform change
  coalesced; platform change then commit before the toggle task; mount / pre-hydration.
- Invisible case: find-in-page hit in content still open during a pending close (no event).
- Overlays already use a source marker (overlay-show.ts). Fixed stale "intended -> echo"
  walkthrough lines in menu.md / dialog.md.
