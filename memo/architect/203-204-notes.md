# #203 readOnly, #204 types subpath: working notes (2026-11-28)

Design: conventions 3.6.1, 9.2; CHANGELOG entry "2026-11-28, #203, #204". Status: proposed.

## Sources read

- ARIA editor's draft (w3c/aria `index.html`): `aria-readonly` listed under checkbox, combobox,
  grid, gridcell, listbox, radiogroup, slider, spinbutton, textbox (plus password, window in the
  draft). Not radio, option, button.
- ARIA in HTML 4.2, `readonly` row: MAY on a role that allows it; SHOULD NOT `="true"` next to
  native `readonly`; MUST NOT `="false"` next to it.
- Base UI 1.6 docs (`base-ui.com/react/components/<c>.md`): readOnly + data-readonly on checkbox,
  radio-group (Radio and Group), switch, select, combobox, number-field; absent on slider,
  checkbox-group, toggle, toggle-group, field, fieldset.
- React Aria and Ark UI: from memory only, not re-read. Say so if quoted.

## Mechanism choices and why

- Checkables: cancel the click from React's `onChange` (the synthetic event wraps the native
  click). Keeps `onClick` unowned, so conventions 1.5 does not force `onClick` out of five props
  types. Unverified in a browser: needs rows in all three engines (radio arrows especially).
- Rejected for checkables: "dispatch nothing and let React's controlled restore undo it". Works,
  but `input` / `change` still fire and the Field hears them.
- Select: disabled unselected options. A selected+disabled option is not submitted, which is why
  the options must follow the optimistic value (after a reset the new selection is the enabled
  one in the next render).
- Slider: AT increment actions change a native range with no `keydown`; hence the write-back
  fallback in 3.6.1 rule 6.
- Validation: server errors block through the custom-validity slot until an edit; a read-only
  control can never be edited, so the slot must stay empty or Save is dead.

## Not decided here

- Item-level readOnly (one locked box in a CheckboxGroup): needs Parent arithmetic.
- Checkbox with a consumer `role` that has no read-only state (`option`, `button`): the mark is
  still rendered; revisit if Menu ever renders a Checkbox that way.
