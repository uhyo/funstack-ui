# #115 and #116: overlay Trigger clicks while open

Branch `fix/115-116-trigger-close`.

## #115 (non-button Popover / Menu Trigger)

- No behaviour change. `usePopoverTrigger`'s `useElementCheck` now warns in library mode too for
  a non-button Trigger: a press while open is a light dismiss before the click (not awaited, no
  veto, no exit transition). JS-free text unchanged. Dev-only (`isDev &&`), production-bundle
  test green.
- The hook is shared. A non-button `Menu.SubmenuTrigger` (review F3): a press while its submenu
  is open dismisses the submenu with `(false, "dismiss")` and focus stays on the trigger (a
  `<button>` keeps it open and moves focus into it). It gets its own warning text through the
  `opensOnly` option (not `activate !== undefined`: Menu.Trigger passes `activate` too).
- Review F4: `commandfor` / `command` only on a `<button>` or a component render, at each call
  site (`usePopoverTrigger`, `DialogTrigger`, `useOverlayClose`), never in
  `disabledButton().invoker` (Close's `aria-disabled` is derived from it). Menu's press-drag
  `inSubmenuOf` read the SubmenuTrigger's `commandfor`; it now asks the hover registration
  (`SubmenuHover.popup`). Test: menu-context-trigger.test "a move from a <div> SubmenuTrigger
  onto the submenu's padding" fails with the old lookup.
- Tests: jsdom rows in popover.test.tsx (library-mode text, no warning for a button in either
  mode) and menu.test.tsx; browser row "non-button Trigger click while open (browser, #115)" in
  popover.browser.test.tsx: split real press on `<a>`, hidden before the click while the close
  action is pending, one `(false, "activate")` from the click.
- Mutation: dropping the library-mode branch fails both jsdom rows.

## #116 (Trigger click on an open non-modal lightDismiss Dialog)

- Behaviour change, for the release notes: the JS light-dismiss baseline of `Dialog.Popup`
  (`isOutside` in dialog-popup.tsx) no longer excludes the Trigger. A click on the Trigger of an
  open non-modal `lightDismiss` dialog now closes it with `(false, "dismiss")` (event: `close`)
  on every engine, with or without `experimental_closedBy`, matching native `closedby="any"`.
  Before, it stayed open without the flag and on WebKit. Modal dialogs and dialogs without
  `lightDismiss` are unchanged.
- `triggerRef` dropped from the light-dismiss effect's deps (no longer read there).
- JSDoc of `lightDismiss` and the DialogPage row say the Trigger counts as outside.
- Tests: jsdom `it.each` in dialog.test.tsx (flag off, flag on = JS fallback in jsdom); browser
  `it.each` in dialog.browser.test.tsx, own describe block, branching on
  `supportsDialogClosedBy` only for which mechanism called `requestClose`.
- Mutation (re-adding the Trigger exclusion): both jsdom rows fail; on Chromium / Firefox the
  browser row without the flag fails (the flag row passes there because the native path never
  had the exclusion; on WebKit both would fail).

### Review follow-ups (#116)

- F1: JS-free non-modal `lightDismiss` used to close and then re-open on a Trigger click (the
  Trigger's `!dialog.open` check ran after the dismissal), natively with the flag even on
  master. `DialogTrigger` now records `dialog.open` at `pointerdown` (owned `onPointerDown`,
  non-modal JS-free only) and skips `show()` on a pointer click (`detail > 0`) whose press saw it
  open. Keyboard clicks have `detail` 0, so a stale press cannot swallow them. Mutations: removing
  the guard fails the jsdom and browser JS-free rows (both flags); dropping the `detail` check
  fails the stale-press row.
- F2: a Trigger click during a pending part close with `lightDismiss` ends closed:
  `[true, false activate, true, false dismiss]`. Row in dialog-close.test.tsx.

## Release notes (behaviour changes)

- Dialog: a click on the Trigger of an open non-modal `lightDismiss` dialog now dismisses it
  (`openChangeAction(false, { reason: "dismiss" })`) on every engine, with or without
  `experimental_closedBy`, in library and JS-free mode, as native `closedby="any"` does. It used
  to stay open (JS path, WebKit) or, in JS-free mode with the flag, close and re-open.
- Dialog: with `lightDismiss`, a Trigger click during a pending part-initiated close (an async
  Close) now ends closed (the dismissal is the last intent) instead of re-opening.
- Popover / Menu / Dialog: a Trigger or Close rendered as a host element other than a `<button>`
  (for example `render={<a href />}`) no longer gets `commandfor` / `command` attributes.
- Popover / Menu: new development warning for a non-button Trigger / SubmenuTrigger in library
  mode.
