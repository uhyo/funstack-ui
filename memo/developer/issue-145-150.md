## #145

- `internal/use-superseded-rejection.ts` deleted. Replaced by `internal/report-superseded.ts`:
  `reportSuperseded(error)` = global `reportError`, `console.error` where there is none.
- `useControllableAction` / `useActionTrigger`: catch -> settle -> latest: rethrow (boundary);
  otherwise `reportSuperseded` and return. No state, no hook-order constraint, no
  `captureSuperseded` option (removed from both option types; Slider and NumberField no longer
  create a shared capture).
- After unmount a superseded rejection is still reported (B has no mounted check; the old hook
  dropped it). React drops the latest run's rejection after unmount on its own. Flag for the
  architect: decide whether "reported after unmount" is the contract.
- Every superseded rejection of a burst is reported (no "first one kept" rule any more).

### jsdom / vitest and reportError

- vitest's jsdom environment does NOT expose `reportError` (`typeof reportError ===
  "undefined"`, also on `window`). So in jsdom the fallback `console.error` runs; tests stub
  `reportError` with `vi.stubGlobal` (the setup's afterEach unstubs globals) and assert on the mock.
- In a real browser `reportError` dispatches a window `error` event, which vitest browser mode
  reports as an unhandled error (fails the run). Any browser test that makes an older action
  reject must stub `reportError`. None does today.

## #150

Repro (value-action-suite row "commits only the settled changes when the older action rejects
before/after the newer resolves", uncontrolled, with #145 applied and before the fix): failed
for CheckboxGroup (expected [] got [a]), ToggleGroup multiple and Accordion multiple, both orders.
Passed for Toggle, Tabs, Accordion exclusive (single-valued). So the bug was real; before #145 it
was masked by the boundary replacing the UI.

Fix in `useControllableAction`: with a `reducer` and uncontrolled, each dispatch is recorded in a
burst list; when the in-flight count reaches 0, the resolved entries are folded with the reducer
onto the committed value (functional `setInternal` in `startTransition`), in dispatch order;
rejected entries are skipped. Without a reducer: unchanged latest-dispatch guard. Commit timing
is unchanged in practice (React holds transition writes until the whole entangled action scope
settles anyway).

Found while fixing: ToggleGroup **exclusive** uses the same reducer (`applyPatch`) and its patch's
`removed` is computed from the optimistic value, so folding "press center (rejected), press right
(resolved)" from `left` gave `{left, right}`. Reducer now replaces the value for an exclusive
press (`added` non-empty -> `new Set(added)`). Row added in toggle-group.test.tsx.

Edge not handled: Accordion's mount reconciliation dispatch (reason "platform", no event) carries
a whole `next` that its reducer adopts wholesale; if it lands in a burst behind a click that later
rejects, the fold includes that click. Probably unreachable (the mount reconciliation runs in the
mount effects, before a library-mode click can dispatch), not probed.

## Review fixes (memo/reviewer/review-145-150.md)

- Exclusive ToggleGroup and exclusive Accordion now pass **no reducer**: single-valued, the
  latest-dispatch guard commits `next` (like Tabs). My earlier "exclusive press replaces" reducer
  only covered presses; a rejected press then a resolved release brought the old item back.
- CheckboxGroup reducer adopts `next` whole for a form reset (reason "platform" with an event;
  only the reset passes an event to `onPlatformChange`). The mount / late-mount reconciliations
  stay patches. ToggleGroup and Accordion have no form reset, so no counterpart there.
- Residual, not fixed: a reset whose target equals the intended value dispatches nothing
  (`useNativeGroupReconciliation` compares with `base()`), so if an in-flight uncheck then
  rejects, the earlier committed value comes back after a reset. Same outcome as without a reset.
- The dispatch-order unit row is now discriminating (a on, a off, b on, c on; 2 before 1, 3
  rejects, 4 resolves -> {c}); checked it fails with the latest-dispatch commit ({b,c}).
- All five new component rows fail on b6df202's sources (checked by swapping the three root
  files back).
