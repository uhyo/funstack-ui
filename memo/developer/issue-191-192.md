# #191 / #192: Escape rule (branch fix/191-192-escape)

- Audit of `"Escape"` in packages/ui/src (non-test): dialog-dismiss (record), hover-card
  (document + trigger), tooltip (document + trigger), toast-root, menubar hold, combobox chip.
  Everything else (Popover, Menu, Combobox list, Select, MultiSelect) leaves Escape to the
  `auto` popover close watcher. NumberField / OTPField handle no Escape.
- Shared check: `internal/escape-key.ts` `isEscapeRequest` (key, !defaultPrevented,
  !isComposing, keyCode !== 229) and `isComposingKey`. Rule written as conventions 15.
- Combobox chip left untouched (other dev on #193 in combobox-root.tsx; chip's 229/Process
  handover precedes its Escape case anyway). combobox-keyboard.ts: one-line swap to
  `isComposingKey` only.
- Chromium CDP probe (scratch, deleted): imeSetComposition + rawKeyDown Escape vk 229 ->
  keydown key=Escape keyCode=229 isComposing=true, no compositionend, modal dialog and auto
  popover stay open. vk 27 -> keydown isComposing=true, compositionend, close watcher closes.
- Mutation: `isEscapeRequest = key === "Escape"` fails all 13 new jsdom rows (+ the old
  HoverCard prevented row) and all 8 non-native browser rows (chromium + firefox).
- Browser rows use `vitest/browser` `cdp()` on Chromium only; untrusted synthetic keydowns
  elsewhere.
