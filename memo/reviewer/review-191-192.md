## Should-fix
1. toast-root.tsx:257-261 vs use-tooltip-interaction.ts:151-161. Toast's React onKeyDown runs at
   the React root, before every document listener, so a Tooltip (or HoverCard) shown inside a
   toast never gets the Escape first. Probe (Chromium, tooltip on a focused button inside a toast
   with an exit transition): branch -> toast dismisses, tooltip still :popover-open after the
   keydown (hides only later via blur + closeDelay 150); master -> both close at once. Neither
   is innermost first. Fix: Toast stands down when an open popover/dialog is inside its Root
   (HoverCard's containsOpenLayer, use-hover-card-interest.ts:355), plus a row. Pre-existing for
   HoverCard-in-Toast. Conventions 15 rule 2 "innermost first" only holds when the inner
   listener runs earlier in propagation; say so or fix Toast.

## Nits

   engines; off Chromium the untrusted keydowns can never run a close watcher, so it is vacuous
   there. Name it accordingly or assert only on Chromium with a stated reason.
3. escape-ime.browser.test.tsx:51-65 Firefox/WebKit rows replay jsdom's synthetic shapes; they
   add no engine coverage (CLAUDE.md: browser tests only for what jsdom cannot see). WebKit
   untested locally: whether its KeyboardEvent ctor honours `keyCode` in init is unverified

4. HoverCard IME browser row (:140) passes on master in Chromium (CDP event has isComposing;
   the old guard read it). Not a regression row for the change there.
5. conventions 15 claim "an auto popover stays open" under CDP IME has no kept row (memo: scratch
   probe deleted). Keep a row or drop the claim.
6. Untested new branches: prevented Escape on the Menubar held Trigger (menubar.tsx:185), on the
   HoverCard Trigger cancel (use-hover-card-interest.ts:281) and on Tooltip's trigger cancel
