# FUNSTACK UI Knowledge

**FUNSTACK UI** (`@funstack/ui`) is a headless React component library built on React's async features: actions, transitions, `useOptimistic`, Suspense and `<ViewTransition>`. Components render accessible HTML with `data-*` attributes and ship no visual styles. It is experimental (alpha releases under the `alpha` dist-tag); APIs change between releases, so trust the bundled docs over your memory.

Requirements: `react` and `react-dom` `>=19.3.0` (peer dependencies). ESM only. Supported browsers: the latest stable Chrome/Edge, Safari and Firefox, with no fallbacks for older ones.

## Mental model

- **Action props, not event handlers.** Interactive props are named `action` or `fooAction` (`pressedChangeAction`, `valueChangeAction`, `openChangeAction`, `checkedChangeAction`). The component calls them inside its own React transition and awaits a returned promise. Change actions (`xChangeAction`) take `(next, details)`; task actions (`action` on `Button`, `Menu.Item`, `Dialog.Close`, `Drawer.Close`, `AlertDialog.Cancel`, `AlertDialog.Action`, `Popover.Close`, `Toast.Action`) take only `(details)`, so write `action={() => save()}`, not `action={(next) => ...}`. The return type is `unknown`. `details.event` is the native DOM event; `details.reason` (where present) is `"activate" | "platform" | "dismiss" | "timeout"`.
- **State triple.** A controllable state `x` comes as `x` (controlled), `defaultX` (uncontrolled initial value) and `xChangeAction`. `undefined` means uncontrolled; "nothing selected" is `null`. Do not switch between controlled and uncontrolled after mount.
- **Optimistic and pending are built in.** While an action is pending, triggers (the parts the user acts on) already show the new value, and the state owner (usually the `Root`) and the trigger carry `data-pending`. If the action rejects, the value rolls back and the error goes to the nearest Error Boundary. Uncontrolled state is written only after success. A part that asks its overlay to close (`Dialog.Close`, `Popover.Close`, `Drawer.Close`, `AlertDialog.Cancel` / `Action`, a closing `Menu.Item`) has `data-pending` from the click until that close has committed, with or without `action` (without one it never gets `aria-disabled`): style it to show a close that waits for `openChangeAction(false)` or for another running action.
- **Latest intent wins, for uncontrolled state.** A second click while pending is a new intent: the optimistic display follows it, and uncontrolled state commits only the most recent dispatch (set-valued state, `CheckboxGroup` and non-`exclusive` `ToggleGroup` / `Accordion`, commits every change whose action resolved, in order, and leaves out one whose action rejected; a later action's `next` still includes an earlier pending change, so persist `details.added` / `details.removed`, not the whole `next`; exception: a `CheckboxGroup` form reset, `reason: "platform"` with `details.event?.type === "reset"`, is absolute, so persist its `next` whole, its `added` / `removed` can be empty; to keep saves from overlapping at all, queue them with React's `useActionState`). The rejection of an older action that a newer one superseded does not reach the Error Boundary (as with React's own `useTransition`); the library passes it to the global `reportError`, so it fires the window `error` event and fails a test run that does not stub `reportError`. The same goes for a rejection that arrives after its component unmounted (a toast or menu closed while its action ran) or while `<Activity>` hides it. In controlled mode, your own `setState` after an `await` lands in completion order, so an older response can overwrite a newer one; guard it yourself or queue the calls with React's `useActionState`. A pure trigger (a part that runs a task: `Button`, `Dialog.Close`, `Drawer.Close`, `AlertDialog.Cancel`, `AlertDialog.Action`, `Popover.Close`, `Menu.Item`, `Toast.Action`) has no value to protect; what a click while its own action is pending does is its `whilePending` prop (`"run" | "ignore"`, type `WhilePending`). `"run"` runs the action again (runs overlap; `data-pending` until the last settles, no `aria-disabled`; an older run's rejection goes to `reportError`); `"ignore"` drops the click, cancels its default action and renders `aria-disabled="true"` while pending (not while you have it natively `disabled`: native `disabled` wins). Defaults: `Button` `"run"` (put `whilePending="ignore"` on a Save, Pay or Delete, and on a `formAction` submitter that must not submit twice: React drops an older overlapping submission's rejection); Close parts (`Dialog.Close`, `Drawer.Close`, `Popover.Close`, `AlertDialog.Cancel`, `AlertDialog.Action`) `"ignore"`; `Menu.Item` and `Toast.Action` `"ignore"`, but `"run"` with `closeOnActivate={false}`. Parts are never natively disabled while pending.
- **Content regions show the committed value.** Panels and popup content follow the committed state, so content that suspends keeps the old content on screen until it is ready (with value or open props, an Accordion item, Collapsible, Dialog or Popover stays closed until then; without them their content is rendered ahead and must not suspend). The library never adds `<Suspense>` and has no `fallback` props; you place boundaries.
- **`transition` prop = `<ViewTransition>`.** A part whose mount, unmount or content follows committed library state (a Panel, a library-driven Popup, an `Accordion.Item`) accepts `transition`; passing it wraps the part in `<ViewTransition default={transition}>`. Without it, no boundary is rendered. A part whose rendered state is all optimistic has no `transition` (triggers such as `Tabs.Tab`, `Accordion.Trigger`, `Collapsible.Trigger`; the checkables `Toggle`, `Checkbox`, `Switch`, `RadioGroup.Item`, `CheckboxGroup.Item` / `Parent`, `ToggleGroup.Item`; menu items, Select parts and listbox options): animate it with CSS on its attributes, or wrap its content in your own `<ViewTransition>` keyed on its types. `Button` keeps the prop. Each dispatch is tagged with `fsui-<component>` transition types (for example `fsui-tabs-next`), usable in a type map or `:active-view-transition-type()`. On a popup (`Popover`, `Dialog`, `AlertDialog`, `Drawer`, `Menu`, `HoverCard`, `NavigationMenu`, `Combobox`, `MultiSelect`), write a CSS exit for dismissals next to `transition`: the library turns the popup's CSS transitions off for the moment of its own show or hide while a view transition runs, so an `html:active-view-transition .popup { transition: none }` rule (older docs needed one) is not needed: remove it (keeping it is harmless, but it also cuts a dismissal's fade during an unrelated view transition). Only CSS transitions are cut: write the popup's exit as a `transition`, not a `@keyframes` animation.
- **Browser-owned state.** Where the platform owns the state (popover top layer, `<details open>`, `<dialog>` dismissal, native inputs), the library observes it instead of copying it. Escape and click-outside are browser dismissals, **facts**: they are not passed to `openChangeAction` (requests only) but to `onOpenChange(false, details)`, called synchronously, not awaited, never pending, and they cannot be vetoed. A controlled overlay therefore takes both: `open={open} openChangeAction={setOpen} onOpenChange={setOpen}` (set state directly in `onOpenChange`, never in `startTransition` or after an `await`; a parent that keeps `open={true}` re-opens it).
- **One Escape closes one layer.** Where the library handles Escape itself (a non-modal Dialog or Drawer, Tooltip, HoverCard, a toast) it follows the browser's close watchers: a showing Tooltip or HoverCard closes first (the one that opened first), then the innermost layer around the focus; the next Escape reaches the one outside. To keep a layer open on Escape, call `preventDefault()` on the `keydown`; `stopPropagation()` does not keep any of them open (it did not for a modal dialog either). An Escape during an IME composition closes nothing.
- **Headless.** No provider, no theme, no stylesheet. Style with your CSS on `data-*` attributes (present as `data-x=""` when true, absent when false; enum states carry a value, `data-orientation="vertical"`). Hover, focus and active are not attributes: use `:hover`, `:focus-visible`, `:active`.

## Things agents get wrong

1. **Do not use `onClick`, `onChange`, `onValueChange`, `onPressedChange`.** They do not exist as library props (the one `onValueChange` is `OTPField.Root`'s, below). Handlers a part installs on its element in any mode (for example `onClick` on `Toggle` or `Form.Submit`, `onPointerDown` on `Dialog.Trigger`, `onPointerMove` on `Menu.Trigger`) are removed from its props type in every mode; for the raw event put a handler on the `render` element (it runs first) or use `ref` with `addEventListener`. Unused DOM handlers pass through to the element. The library's own `on*` props report **facts** (changes that had already happened when the library heard of them, such as a popup dismissed with Escape): `onOpenChange` on the nine owners of an overlay's `open`: `Popover.Root`, `Menu.Root`, `Combobox.Root`, `MultiSelect.Root`, `Dialog.Root`, `AlertDialog.Root`, `Drawer.Root`, `HoverCard.Root` and `NavigationMenu.Item` (closes the library did not perform, always `false`; no other part has it: not Tooltip, Accordion or Collapsible), `Combobox.Root`'s `onInputValueChange` (input text), `OTPField.Root`'s `onValueChange` (the code's text), and a toast's `onClose` (`toast({ onClose })`, formerly `closeAction`). Each is called synchronously, outside any transition, not awaited; it may return a promise; a rejection, or a throw, goes to `reportError`.
2. **Do not wrap the action in `startTransition` yourself**, and do not add `useOptimistic` or a pending flag around a component: it already does this. But a `setState` that runs **after your own `await`** inside an action is outside the transition (a React rule); wrap that one in `startTransition`.
3. **Return a promise only if the UI must wait for it.** A pending async action holds every other transition in the app (including router navigations). For background work, do not return the promise: `valueChangeAction={(v) => { void save(v); }}`.
4. **No `asChild`, no `as`.** Use `render`: `render={<MyButton />}` (the element must accept `ref` and spread its props) or `render={(props, state) => <a {...props} />}`.
5. **`className`, `style` and `children` may be functions of the part's state**, for example `className={({ pending }) => ...}`. Trigger `children` render from optimistic state and must not suspend.
6. **Import from subpaths**: `import { Tabs } from "@funstack/ui/tabs"`. The root entry also works. Shared types (`Action`, `ActionDetails`, `ChangeAction`, `ChangeReason`, `RenderProp`, `StateValue`, `UrgentChangeHandler`, `UrgentHandler`, `WhilePending`) come from the types-only subpath: `import type { ChangeReason } from "@funstack/ui/types"` (the root exports them too; component subpaths do not). A component's own types (`TabsValueChangeDetails`) come from its subpath.
7. **Compound components are namespaces of parts** (`Tabs.Root`, `Tabs.Tab`). The namespace itself is not a component.
8. **Do not add polyfills or JS fallbacks** for the Popover API, `<dialog>`, CSS Anchor Positioning or Invoker Commands. Features not in every engine yet are opt-in `experimental_*` props.
9. **Server Components**: parts are `"use client"` modules, so a Server Component can render them, but it can only pass serialisable props. A Server Function (`"use server"`) can be passed directly to any action prop; a plain function cannot.
10. **Panels never get `data-pending`.** To style content while the next one loads, select through the Root (`.tabs[data-pending] .panel { opacity: .6 }`). Dialog and Popover Roots render no element: use the Trigger's `data-pending` instead.
11. **Toasts need a viewport.** Render `<Toast.Viewport>` once (its `children` is a function of `{ toasts }`), then call `toast({ title })` anywhere on the client.
12. **No `DirectionProvider`, no `LocaleProvider`.** Right-to-left is the native `dir` attribute (on `<html>`, a container or a part); components read the computed CSS `direction`, and only ArrowLeft / ArrowRight of a horizontal orientation mirror. `OTPField.Root` renders `dir="ltr"` unless you pass `dir`. `locale` (`string | readonly string[]`) is a prop of `NumberField.Root`, `Progress.Root` and `Meter.Root`; pass it on server-rendered pages. Docs page: `concepts/direction-and-locales`.

## Component index

Each line: import path, parts, main state props.

- `Button` (`@funstack/ui/button`): `action` (pure trigger; a click while pending runs again unless `whilePending="ignore"`), `formAction`, `whilePending`.
- `Toggle` (`@funstack/ui/toggle`): `pressed` / `defaultPressed` / `pressedChangeAction` (`details.reason` is always `"activate"`). No `transition` prop (everything it renders is optimistic): animate `[data-pressed]` with CSS, or wrap the content in your own `<ViewTransition>` keyed on `fsui-toggle`.
- `ToggleGroup` (`@funstack/ui/toggle-group`): `Root`, `Item`. `value` is `readonly string[]`, or `string | null` with `exclusive` (types `ToggleGroupRootMultipleProps` / `ToggleGroupRootExclusiveProps`); `details` is `{ reason: "activate", added, removed }` (an exclusive switch lists the released Item in `removed`). No `transition` on any part. Flag `experimental_focusGroup` (camelCase); `focusgroup` on the Root and `focusgroupstart` on an Item are owned (not props; removed without the flag).
- `Toolbar` (`@funstack/ui/toolbar`): `Root`, `Separator`. Any focusable descendant is an item; no item part. `focusgroup` on the Root is owned (use `experimental_focusGroup`). Inside it a disabled `Button`, `Toggle`, `ToggleGroup.Item` or overlay Trigger is `aria-disabled`, focusable and in the arrow sequence (style `[data-disabled]`, not `:disabled`); outside a Toolbar a disabled Toggle / ToggleGroup Item is natively disabled.
- `Tabs` (`@funstack/ui/tabs`): `Root`, `List`, `Tab`, `Panel`, `Indicator`. `value` / `valueChangeAction`; `Panel` takes `transition`, `keepMounted`; `Tab` has no `transition` (all optimistic). `role`, `type`, `tabIndex`, `aria-selected`, `aria-disabled`, `aria-orientation` are owned: do not pass them (use `disabled`). Flag `experimental_focusGroup` on the List; `focusgroup` (List) and `focusgroupstart` (Tab) are owned, not props, and removed without the flag.
- `Accordion` (`@funstack/ui/accordion`): `Root`, `Item` (`<details>`), `Trigger` (`<summary>`, first child of the Item), `Panel`. Without value props it needs no JavaScript; `exclusive` for one open item. `details` is `{ reason, added, removed }` like every set-valued component (an exclusive switch from A to B is `added: ["b"]`, `removed: ["a"]`); `state.value` on the Root is always an array; `state.open` is `false` in JS-free mode (style with `:open`). The arrow keys, Home and End reach disabled Triggers; `loop` (default `true`). `transition` on Item and Panel only; types `fsui-accordion-open` / `-close`.
- `Collapsible` (`@funstack/ui/collapsible`): `Root` (the `<details>` itself), `Trigger` (`<summary>`, first child of the Root), `Panel`. One disclosure; use it rather than a lone `Accordion.Item`. `open` / `defaultOpen` / `openChangeAction` (no `onOpenChange`: find-in-page arrives as `reason: "platform"`); with none of them it needs no JavaScript, and `defaultOpen` alone (even `false`) selects library mode. `state.open` is `false` in JS-free mode; `transition` on Root and Panel only (not the Trigger); types `fsui-collapsible-open` / `-close`.
- `NavigationMenu` (`@funstack/ui/navigation-menu`): a site's main navigation, the disclosure pattern (no menu roles, no arrow keys, Tab through everything). `Root` (`nav`; name it), `List` (`ul[role=list]`), `Item` (`li`; owns one panel's open state with Popover's props), `Trigger` (`button[popovertarget]`), `Popup` (`div[popover=auto]`, no role; render it immediately after the Trigger), `Link` (`a`; `render={<RouterLink />}`; mark the current page with `aria-current="page"` yourself). Without open props on an Item it needs no JavaScript (the browser toggles, keeps one panel open, Escape, light dismiss) and the whole navigation can be written in a Server Component. After hydration focus leaving an Item and a followed `Link` inside a Popup (primary button, no modifier; `closeOnActivate={false}` opts out) close the panel. `openChangeAction` on an Item selects library mode: content that suspends holds the open (Trigger `data-pending`), `transition` on the Popup. The Link's close does not wait for a router's next page. Opens on click only. In library mode the Item's `li` carries `data-open` (optimistic) and `data-pending`.
- `Tooltip` (`@funstack/ui/tooltip`): `Root`, `Trigger`, `Popup`, `Arrow`. Open state is the browser's (no open props); `delay`, `closeDelay`.
- `HoverCard` (`@funstack/ui/hover-card`): `Root`, `Trigger` (a link), `Popup` (render it right after the Trigger; `render={<span />}` inside running text). Opens on hover or keyboard focus after `delay` (600) as a request (`openChangeAction(true)`, content mounts in the transition and may suspend, Trigger `data-pending`); every close (lost interest after `closeDelay` 300, Escape, a press outside or on the link) is a fact for `onOpenChange(false)`. Content must be supplementary (nothing on touch); a click-to-open card is a Popover.
- `Popover` (`@funstack/ui/popover`): `Root`, `Trigger`, `Popup`, `Close`, `Title`, `Description`. `open` / `openChangeAction` (requests) / `onOpenChange` (dismissals); without open props it needs no JavaScript. In that JS-free mode the Trigger's `data-open` still follows the popup (written from its `toggle`), while `state.open` stays `false`: style `[data-open]`, not a `className` function. Inside a `Toolbar.Root` a disabled overlay Trigger (Popover, Dialog, AlertDialog, Drawer, Menu) is `aria-disabled`, focusable and in the arrow sequence: style `[data-disabled]`, not `:disabled`. The invoker attributes, `type` and `aria-disabled` of the Trigger and Close parts are owned and not in their props types.
- `Dialog` (`@funstack/ui/dialog`): `Root`, `Trigger`, `Popup` (`<dialog>`), `Close`, `Form`, `Title`, `Description`. Same modes as Popover; `Dialog.Form` closes after its form action settles. A `Close` with `action` (Dialog or Popover) renders no native command, so it does nothing before hydration; the JS-free way to run work and close is `Dialog.Form` with a Server Function.
- `AlertDialog` (`@funstack/ui/alert-dialog`): a Dialog for confirmations. `Root` (no `modal`: always modal), `Trigger`, `Popup` (`<dialog role="alertdialog">`, no `lightDismiss`: a backdrop click does nothing), `Title`, `Description` (expected: dev warning without one), `Cancel` (focused on open; `initialFocus` on the Popup overrides), `Action`, `Form`. Put the confirmed work in `<AlertDialog.Action action={() => deleteProject(id)}>`: it pends on the button and closes the dialog when it resolves; a rejection keeps it open (place an Error Boundary inside the Popup to show it; a caught error resolves and closes). An Action with `action` does nothing before hydration (as every Close part with `action`); the confirm that works without JavaScript is `AlertDialog.Form action={serverFunction}` with a plain submit button. Escape always closes it (a fact for `onOpenChange`; no prop turns it off), and so does Cancel while the Action is pending (in library mode that close waits for the action to settle and the Cancel has `data-pending` meanwhile, without `aria-disabled`: style `[data-pending]` on it, or disable Cancel with your own `useOptimistic` flag set inside the action when the work is slow). Same transition types and data attributes as Dialog.
- `Drawer` (`@funstack/ui/drawer`): a Dialog on an edge that the user can swipe away (a sheet). Same parts as Dialog (`Root`, `Trigger`, `Popup`, `Title`, `Description`, `Close`, `Form`), each running Dialog's code. `Drawer.Popup` adds `side` (`"top" | "bottom" | "left" | "right" | "inline-start" | "inline-end"`, default `"bottom"`, rendered as `data-side`; the library places nothing, your CSS does) and `swipeDismiss` (default `true`: mouse, pen and touch drag toward the edge; past 25% of the drawer or a 0.5 px/ms flick it closes, as a dismissal for `onOpenChange` with `details.event.type === "pointerup"`, never `openChangeAction`); `lightDismiss` defaults to the Root's `modal`. While dragging the Popup has `data-swiping` and inline `--drawer-swipe-x` / `--drawer-swipe-y` (px) / `--drawer-swipe-progress` (0 to 1): style `.drawer:open { translate: var(--drawer-swipe-x, 0px) var(--drawer-swipe-y, 0px) }`, a CSS `transition` on `translate` (the release waits for it, then closes), `[data-swiping] { transition: none }`, and closed positions inside `:where()` so `:open` wins. A press inside a scroll container along the drawer's axis never drags: a bottom sheet scrolls in a child with `overflow-y: auto` (the dialog `overflow: hidden`); the Popup renders an inline `touch-action`. Always render a `Drawer.Close` (dev warning without one). In a side drawer, `overflow-y: auto` on a child makes `overflow-x` compute to `auto`, so presses in that list never swipe (dev warning); give the list `overflow-x: hidden; touch-action: pan-y pinch-zoom` to swipe from it. Opt a region out with `onPointerDown={(e) => e.preventDefault()}`, which also stops a mouse press there from focusing or selecting: only on non-focusable regions (a map, a canvas). Scale the swipe variables only under `[data-swiping]` (the release writes the full extent). No snap points, no handle part, no background scaling (CSS recipe). Transition types `fsui-drawer*`.
- `Menu` (`@funstack/ui/menu`): `Root`, `Trigger`, `Popup`, `Item` (`action`), `CheckboxItem`, `RadioGroup`, `RadioItem`, `Group`, `GroupLabel`, `Separator`, `SubmenuTrigger`, `ContextTrigger` (context menu). A `Root` inside a `Popup` is a submenu; its Popup has `data-submenu`. `Menu.Trigger` owns its `id`, `role` and `onPointerMove` (not in its props type: the menu is named by the Trigger's generated id); the items own `type`, `role`, `tabIndex` and `aria-disabled` (use `disabled`), `SubmenuTrigger` also `id`, `Menu.Popup` `tabIndex` and `focusgroup` (use `experimental_focusGroup`), and `Menu.Separator` renders and owns `role="separator"` (a `render={<div />}` needs no role).
- `Menubar` (`@funstack/ui/menubar`): one element, `<div role="menubar">`, around ordinary top-level `Menu.Root`s (no `Menubar.Menu` / `Menubar.Trigger`: use the Menu parts). Name it with `aria-label`; `loop` (default `true`). Each `Menu.Trigger` inside becomes an item of the bar (`role="menuitem"`, one Tab stop, Left / Right / Home / End; `disabled` renders `aria-disabled` and stays focusable; do not pass `tabIndex`). Each menu keeps its own `open` / `openChangeAction` / `onOpenChange`; the bar holds no state. A switch (ArrowRight / ArrowLeft inside a menu, the arrows on the Trigger of an open menu, the pointer moving onto another Trigger while a menu is open) closes the old menu as a dismissal (`onOpenChange(false, "dismiss")`) and requests the new one (`openChangeAction(true, "activate")`, `data-pending` on its Trigger while items load). Hover does nothing while every menu is closed. Application menus only; site navigation is not a menubar. No vertical orientation (the bar renders `aria-orientation` / `data-orientation="horizontal"`), no typeahead between Triggers, no items directly in the bar.
- `Toast` (`@funstack/ui/toast`): `toast()` (also `toast.promise`, `toast.update`, `toast.dismiss`), `createToastManager`, parts `Viewport`, `Root`, `Title`, `Description`, `Action`, `Close`. `Toast.Action` closes the toast once its `action` resolves (`closeOnActivate`, default `true`; the old name `closeOnSettle` is gone). `Toast.Action` and `Toast.Close` own `type`, `onClick` and `aria-disabled` (not in their props types).
- `Field` (`@funstack/ui/field`): `Root`, `Label`, `Control`, `Description`, `Error`. Native constraint validation, no validation engine. A textarea is `<Field.Control render={<textarea />} />`, grown with CSS `field-sizing: content` (no auto-size prop). `Field.Control` also works outside a `Field.Root` as the plain control (it takes `id` there; the other parts throw). There is no Input, Textarea or Fieldset part: use the native elements, and group Fields in a native `<fieldset>` / `<legend>` (`<fieldset disabled>` disables every FUNSTACK control inside, but their `data-disabled` does not see it: select `:disabled`). Never disable a fieldset because a submission is pending (focus is lost); use `form[data-pending]`.
- `Form` (`@funstack/ui/form`): `Root` (`action`, `errors` for server errors per field), `Submit`. `Form.Submit` owns `onClick` and `aria-disabled` (not props: use `disabled`; tell submit buttons apart by their `name` / `value` in the `FormData`). `Field.Label` owns `onClick`.
- `Checkbox` (`@funstack/ui/checkbox`): native checkbox; `checked` / `checkedChangeAction`, controlled-only `indeterminate`. No `transition` (a type error; animate with CSS on `:checked`). `readOnly` is the library's (the click is cancelled; `aria-readonly`, `data-readonly`), not the HTML attribute. Types `fsui-checkbox-check` / `-uncheck`.
- `CheckboxGroup` (`@funstack/ui/checkbox-group`): `Root`, `Label`, `Item`, `Parent` (select-all). `value` is `readonly string[]`. `readOnly` is the Root's (no `transition`, no `readOnly` on Item / Parent).
- `RadioGroup` (`@funstack/ui/radio-group`): `Root`, `Label`, `Item`. Native radios; `value` / `valueChangeAction`. `readOnly` is the Root's (`aria-readonly` on the radiogroup; the arrows still move focus); no `transition`, no `readOnly` on Item.
- `Switch` (`@funstack/ui/switch`): native `<input type="checkbox" role="switch">`; `checked` / `checkedChangeAction`. No `transition`; `readOnly` as Checkbox. Types `fsui-switch-check` / `fsui-switch-uncheck` (not `-on` / `-off`).
- Form controls: a disabled control (its own `disabled` or `Field.Root disabled`) is never submitted, Combobox and MultiSelect included. **`readOnly`** is on every form value control (TextField, NumberField, OTPField, Checkbox, Switch, RadioGroup, CheckboxGroup, Select, Combobox, MultiSelect, Slider; on the Root, never on an Item, Option, Thumb or Input part) and on `Field.Root`: focusable, submitted, not changeable, never dispatching, never blocking a submission (native `required` withheld). Style `[data-readonly]` (not `:read-only`, which matches every checkbox and `div`). A read-only Select disables its other options; a read-only Combobox or MultiSelect never opens its popup. Toggle and ToggleGroup have no `readOnly` (use `disabled`). Inside a `Field.Root` every control's state has `invalid` (with `data-invalid`), and `required` where it takes one. An unnamed control logs a development warning.
- `Select` (`@funstack/ui/select`): a real `<select>`. `Root`, `Trigger`, `Value`, `Option`, `Group`, `GroupLabel`, `Separator`. Styled picker via CSS `appearance: base-select`. Single value only: `<Select.Root multiple>` is a type error (dropped with a dev warning); use `MultiSelect`.
- `Combobox` (`@funstack/ui/combobox`): `Root`, `Label`, `Input`, `Trigger`, `Clear`, `Popup`, `List`, `Option`, `Group`, `GroupLabel`, `Empty`, `Status`, and with `multiple` `Chips`, `Chip`, `ChipRemove`. You render the options (no built-in filtering); `List` children get the deferred `query`; `inputValue` / `onInputValueChange` is urgent. Escape with the listbox closed and edited text reverts the text to the committed value's text (single: the selection's label; `multiple`: clears the search) through `onInputValueChange` with `reason: "dismiss"`, and is consumed (an enclosing Dialog stays open for that Escape); an Escape while the listbox is still opening cancels the open and keeps the text, like Escape on a shown listbox. `Combobox.Input` has `data-empty` while nothing is selected ("has a value" is `:not([data-empty])`; there is no `data-selected` on the Input); `readOnly` goes on the Root, not the Input. Props types: `ComboboxRootSingleProps` / `ComboboxRootMultipleProps`. `Root multiple`: `value` is `readonly string[]` (pick order; `next` is a fresh `string[]`), `valueChangeAction(next, { added, removed })` (persist the diff); a pick toggles, clears the text and keeps the listbox open; render chips with `<Combobox.Chips>{({ value }) => value.map((v) => <Combobox.Chip key={v} value={v} />)}</Combobox.Chips>` next to the Input (not around it).
- `MultiSelect` (`@funstack/ui/multi-select`): a select-only combobox for several values (JS listbox on a popover; nothing opens before hydration). `Root`, `Label`, `Trigger` (`button[role=combobox]`, the Tab stop), `Value`, `Popup`, `List`, `Option`, `Group`, `GroupLabel`, `Empty`, `Status`. `value` is `readonly string[]` (pick order; `next` is a fresh `string[]`), `valueChangeAction(next, { added, removed })` (persist the diff); a pick toggles and keeps the listbox open; full open-state API (`open`, `openChangeAction`, `onOpenChange`). Show the selection with `<MultiSelect.Value>{({ value }) => value.map((v) => names[v]).join(", ")}</MultiSelect.Value>` (the library knows a label only after the option was rendered once); the Value has `data-empty` (not `data-placeholder`) while nothing is selected. `required` (at least one) blocks the submit with no browser bubble: put it in a `Field.Root` with `Field.Error` for the message. No chips, no search, no Clear: for those use `Combobox multiple`.
- `Slider` (`@funstack/ui/slider`): `Root`, `Label`, `Track`, `Indicator`, `Thumb`, `Value`. `valueChangeAction` per step, `valueCommitAction` once per gesture; `value` is a number or `number[]`.
- `NumberField` (`@funstack/ui/number-field`): `Root`, `Label`, `Input`, `Increment`, `Decrement`. Locale-formatted; `valueChangeAction` (`NumberFieldValueChangeDetails`), `valueCommitAction` (`NumberFieldValueCommitDetails`). Escape with an edited draft reverts it and is consumed (an enclosing Dialog stays open; the next Escape closes it).
- `OTPField` (`@funstack/ui/otp-field`): `Root` (`length` required, `charset` `"numeric"` default / `"alphanumeric"` / `"alphabetic"`), `Input` (the one `<input autocomplete="one-time-code">`; name it with a `<label for>`, `Field.Label` or `aria-label`), `Slot` (`index` required; `aria-hidden`, `data-filled`, `data-active`). The text is urgent: `value` / `defaultValue` / `onValueChange(next, details)` (a fact, no transition). `completeAction(value, details)` runs in the Root's transition each time an edit leaves the code complete (`data-pending` on Root and Input; every completion runs, no `whilePending`; not at mount, reset or a controlled change); a wrong code is not an error: resolve and show a message, `setCode("")` to clear. `submitOnComplete` (default `false`) calls `requestSubmit()` on the Input's form (tell the user before the field; keep a submit button). `experimental_webOTP` asks for the SMS code (Chromium, Safari). Pasted `123 456` becomes `123456`; no `maxlength`; text typed before hydration is invisible until hydration (use the `@media (scripting: none)` recipe on the docs page for no-JS pages).
- `TextField` (`@funstack/ui/text-field`): one element, a text field that saves itself. `<input type="text">` by default, `render={<textarea rows={4} />}` for several lines; supported types `text`, `tel`, `url`, `email`, `password` (others warn; `type="search"` is not supported, because the browser's Escape clear of a search field would give Escape two meanings: use `type="text"` with `role="searchbox"` and `enterKeyHint="search"`). `value` / `defaultValue` (`string`) are the **saved** text; the typed text is an internal draft. `valueCommitAction(next, details)` (`TextFieldValueCommitDetails`) runs once per edit, on blur or the commit key (Enter in an `<input>`, not prevented, so a form's implicit submission follows; Ctrl+Enter / Cmd+Enter in a `<textarea>`, either on every platform, always prevented and never submitting a form, while Enter / Shift+Enter is a new line and Alt+Enter is not the field's key; no prop changes the key), in the field's transition with `data-pending`; there is no `valueChangeAction` and no `onChange`/`onValueChange`. A rejection or a parent that does not adopt shows the saved text again; to keep the text, adopt it and show "Not saved" yourself. Escape with an edited draft reverts it and is consumed. Form reset and text typed before hydration are `"platform"` commits. Inside `Field.Root` it is the Field's control. For Ctrl+Enter to also submit a form, put an `onKeyDown` on the form that calls `event.currentTarget.requestSubmit()` for a textarea target with Ctrl+Enter / Cmd+Enter (not composing: skip `nativeEvent.isComposing` and `keyCode === 229`; do not skip `defaultPrevented`, the field prevents its key): it runs after the field's commit. Not the library's plain text input: with no save of its own use the native `<input>` or `Field.Control`.
- `Progress` (`@funstack/ui/progress`) and `Meter` (`@funstack/ui/meter`): `Root`, `Track`, `Indicator`, `Label`, `Value`. Output only, no actions; the Root renders in a Server Component.
- `Separator` (`@funstack/ui/separator`): a single `<hr role="separator">` (the part writes and owns `role`, so `render={<div />}` is still a separator); `orientation` (`"horizontal"` default, `"vertical"`), `decorative` (`role="none"`, no `aria-orientation`: for a purely visual line; it is also the separator element that is valid inside a Combobox or MultiSelect listbox, where a Group boundary styled in CSS is the other option). `data-orientation` always, `data-decorative` while decorative; reset the `<hr>`'s margin and border in CSS. No `"use client"`: a Server Component may render it. Inside a Toolbar, Menu or Select use their own `Separator` part.
- `Avatar` (`@funstack/ui/avatar`): `Root` (`span`; `alt` is **required**: a name gives `role="img"` + `aria-label`, `alt=""` gives `aria-hidden`; `aria-labelledby` is owned and never rendered), `Image` (`<img alt="">`, in the server HTML; removed once its source failed), `Fallback` (rendered until the image loaded; stack it **under** the image in one CSS grid cell, there is no `delay` prop). `data-status` / `state.status`: `"idle" | "loading" | "loaded" | "error"`, an urgent mirror; no action, no handler prop. Do not add `onLoad` to `Avatar.Image` unless you mean to opt it out of React's commit wait for images under a `<ViewTransition>`; do not wrap it in your own Suspense for the image. Nothing interactive inside the Root (wrap it in the link instead).
- No `ScrollArea`: style a native scroller with `scrollbar-width` / `scrollbar-color` / `scrollbar-gutter`; give one whose content has nothing focusable `tabindex="0"`, a role and a name (Safari gives it no Tab stop otherwise). Recipe page: `components/scroll-area`.
- `CSPProvider`, `STYLE_SHA256` (`@funstack/ui/csp`): for a strict `style-src` Content Security Policy.

## Full documentation

The full documentation (concepts, every component page with props tables, data attributes, keyboard behaviour and recipes) is bundled as Markdown in the installed package, matching its version. Start from the index, which ends with a list of all pages:

```
node_modules/@funstack/ui/dist/docs/index.md
```

Every other page is at `node_modules/@funstack/ui/dist/docs/<route>.md`, for example `components/dialog.md` or `concepts/action-props.md`.

If that file is missing (the package is not installed), use the online docs instead: https://ui.funstack.work/llms.txt lists every page, and each page is also available as Markdown at its URL plus `.md` (for example https://ui.funstack.work/components/dialog.md).
