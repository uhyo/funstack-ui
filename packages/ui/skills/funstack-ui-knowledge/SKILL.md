# FUNSTACK UI Knowledge

**FUNSTACK UI** (`@funstack/ui`) is a headless React component library built on React's async features: actions, transitions, `useOptimistic`, Suspense and `<ViewTransition>`. Components render accessible HTML with `data-*` attributes and ship no visual styles. It is experimental (alpha releases under the `alpha` dist-tag); APIs change between releases, so trust the bundled docs over your memory.

Requirements: `react` and `react-dom` `>=19.3.0` (peer dependencies). ESM only. Supported browsers: the latest stable Chrome/Edge, Safari and Firefox, with no fallbacks for older ones.

## Mental model

- **Action props, not event handlers.** Interactive props are named `action` or `fooAction` (`pressedChangeAction`, `valueChangeAction`, `openChangeAction`, `checkedChangeAction`). The component calls them inside its own React transition and awaits a returned promise. Change actions (`xChangeAction`) take `(next, details)`; task actions (`action` on `Button`, `Menu.Item`, `Dialog.Close`, `AlertDialog.Action`, `Popover.Close`, `Toast.Action`) take only `(details)`, so write `action={() => save()}`, not `action={(next) => ...}`. The return type is `unknown`. `details.event` is the native DOM event; `details.reason` (where present) is `"activate" | "platform" | "dismiss" | "timeout"`.
- **State triple.** A controllable state `x` comes as `x` (controlled), `defaultX` (uncontrolled initial value) and `xChangeAction`. `undefined` means uncontrolled; "nothing selected" is `null`. Do not switch between controlled and uncontrolled after mount.
- **Optimistic and pending are built in.** While an action is pending, triggers (the parts the user acts on) already show the new value, and the state owner (usually the `Root`) and the trigger carry `data-pending`. If the action rejects, the value rolls back and the error goes to the nearest Error Boundary. Uncontrolled state is written only after success.
- **Latest intent wins, for uncontrolled state.** A second click while pending is a new intent: the optimistic display follows it, and uncontrolled state commits only the most recent dispatch (set-valued state, `CheckboxGroup` and non-`exclusive` `ToggleGroup` / `Accordion`, commits every change whose action resolved, in order, and leaves out one whose action rejected; a later action's `next` still includes an earlier pending change, so persist `details.added` / `details.removed`, not the whole `next`; exception: a `CheckboxGroup` form reset, `reason: "platform"` with `details.event?.type === "reset"`, is absolute, so persist its `next` whole, its `added` / `removed` can be empty; to keep saves from overlapping at all, queue them with React's `useActionState`). The rejection of an older action that a newer one superseded does not reach the Error Boundary (as with React's own `useTransition`); the library passes it to the global `reportError`, so it fires the window `error` event and fails a test run that does not stub `reportError`. The same goes for a rejection that arrives after its component unmounted (a toast or menu closed while its action ran) or while `<Activity>` hides it. In controlled mode, your own `setState` after an `await` lands in completion order, so an older response can overwrite a newer one; guard it yourself or queue the calls with React's `useActionState`. A pure trigger (a part that runs a task: `Button`, `Dialog.Close`, `AlertDialog.Cancel`, `AlertDialog.Action`, `Popover.Close`, `Menu.Item`, `Toast.Action`) has no value to protect; what a click while its own action is pending does is its `whilePending` prop (`"run" | "ignore"`, type `WhilePending`). `"run"` runs the action again (runs overlap; `data-pending` until the last settles, no `aria-disabled`; an older run's rejection goes to `reportError`); `"ignore"` drops the click, cancels its default action and renders `aria-disabled="true"` while pending (not while you have it natively `disabled`: native `disabled` wins). Defaults: `Button` `"run"` (put `whilePending="ignore"` on a Save, Pay or Delete, and on a `formAction` submitter that must not submit twice: React drops an older overlapping submission's rejection); Close parts (`Dialog.Close`, `Popover.Close`, `AlertDialog.Cancel`, `AlertDialog.Action`) `"ignore"`; `Menu.Item` and `Toast.Action` `"ignore"`, but `"run"` with `closeOnActivate={false}` / `closeOnSettle={false}`. Parts are never natively disabled while pending.
- **Content regions show the committed value.** Panels and popup content follow the committed state, so content that suspends keeps the old content on screen until it is ready (with value or open props, an Accordion item, Collapsible, Dialog or Popover stays closed until then; without them their content is rendered ahead and must not suspend). The library never adds `<Suspense>` and has no `fallback` props; you place boundaries.
- **`transition` prop = `<ViewTransition>`.** Parts whose content is driven by library state accept `transition`; passing it wraps the part in `<ViewTransition default={transition}>`. Without it, no boundary is rendered. Each dispatch is tagged with `fsui-<component>` transition types (for example `fsui-tabs-next`), usable in a type map or `:active-view-transition-type()`. On a popup (`Dialog`, `Popover`, `Menu`, `Combobox`, `MultiSelect`), write a CSS exit for dismissals next to `transition`: the library turns the popup's CSS transitions off for the moment of its own show or hide while a view transition runs, so an `html:active-view-transition .popup { transition: none }` rule (older docs needed one) is not needed: remove it (keeping it is harmless, but it also cuts a dismissal's fade during an unrelated view transition). Only CSS transitions are cut: write the popup's exit as a `transition`, not a `@keyframes` animation.
- **Browser-owned state.** Where the platform owns the state (popover top layer, `<details open>`, `<dialog>` dismissal, native inputs), the library observes it instead of copying it. Escape and click-outside are browser dismissals, **facts**: they are not passed to `openChangeAction` (requests only) but to `onOpenChange(false, details)`, called synchronously, not awaited, never pending, and they cannot be vetoed. A controlled overlay therefore takes both: `open={open} openChangeAction={setOpen} onOpenChange={setOpen}` (set state directly in `onOpenChange`, never in `startTransition` or after an `await`; a parent that keeps `open={true}` re-opens it).
- **Headless.** No provider, no theme, no stylesheet. Style with your CSS on `data-*` attributes (present as `data-x=""` when true, absent when false; enum states carry a value, `data-orientation="vertical"`). Hover, focus and active are not attributes: use `:hover`, `:focus-visible`, `:active`.

## Things agents get wrong

1. **Do not use `onClick`, `onChange`, `onValueChange`, `onPressedChange`.** They do not exist as library props (the one `onValueChange` is `OTPField.Root`'s, below). Handlers a part installs itself (for example `onClick` on `Toggle`) are removed from its props type; unused DOM handlers pass through to the element. The library's own `on*` props report **facts** (changes that had already happened when the library heard of them, such as a popup dismissed with Escape): `onOpenChange` on `Popover.Root`, `Menu.Root`, `Combobox.Root`, `MultiSelect.Root`, `Dialog.Root` and `AlertDialog.Root` (dismissals only, always `false`), `Combobox.Root`'s `onInputValueChange` (input text), `OTPField.Root`'s `onValueChange` (the code's text), and a toast's `onClose` (`toast({ onClose })`, formerly `closeAction`). Each is called synchronously, outside any transition, not awaited; it may return a promise; a rejection, or a throw, goes to `reportError`.
2. **Do not wrap the action in `startTransition` yourself**, and do not add `useOptimistic` or a pending flag around a component: it already does this. But a `setState` that runs **after your own `await`** inside an action is outside the transition (a React rule); wrap that one in `startTransition`.
3. **Return a promise only if the UI must wait for it.** A pending async action holds every other transition in the app (including router navigations). For background work, do not return the promise: `valueChangeAction={(v) => { void save(v); }}`.
4. **No `asChild`, no `as`.** Use `render`: `render={<MyButton />}` (the element must accept `ref` and spread its props) or `render={(props, state) => <a {...props} />}`.
5. **`className`, `style` and `children` may be functions of the part's state**, for example `className={({ pending }) => ...}`. Trigger `children` render from optimistic state and must not suspend.
6. **Import from subpaths**: `import { Tabs } from "@funstack/ui/tabs"`. The root entry also works; shared types (`ActionDetails`, `ChangeAction`, `ChangeReason`, `RenderProp`, `StateValue`, `UrgentChangeHandler`) are exported from `@funstack/ui`.
7. **Compound components are namespaces of parts** (`Tabs.Root`, `Tabs.Tab`). The namespace itself is not a component.
8. **Do not add polyfills or JS fallbacks** for the Popover API, `<dialog>`, CSS Anchor Positioning or Invoker Commands. Features not in every engine yet are opt-in `experimental_*` props.
9. **Server Components**: parts are `"use client"` modules, so a Server Component can render them, but it can only pass serialisable props. A Server Function (`"use server"`) can be passed directly to any action prop; a plain function cannot.
10. **Panels never get `data-pending`.** To style content while the next one loads, select through the Root (`.tabs[data-pending] .panel { opacity: .6 }`). Dialog and Popover Roots render no element: use the Trigger's `data-pending` instead.
11. **Toasts need a viewport.** Render `<Toast.Viewport>` once (its `children` is a function of `{ toasts }`), then call `toast({ title })` anywhere on the client.

## Component index

Each line: import path, parts, main state props.

- `Button` (`@funstack/ui/button`): `action` (pure trigger; a click while pending runs again unless `whilePending="ignore"`), `formAction`, `whilePending`.
- `Toggle` (`@funstack/ui/toggle`): `pressed` / `defaultPressed` / `pressedChangeAction`.
- `ToggleGroup` (`@funstack/ui/toggle-group`): `Root`, `Item`. `value` is `string[]`, or `string | null` with `exclusive`.
- `Toolbar` (`@funstack/ui/toolbar`): `Root`, `Separator`. Any focusable descendant is an item; no item part.
- `Tabs` (`@funstack/ui/tabs`): `Root`, `List`, `Tab`, `Panel`, `Indicator`. `value` / `valueChangeAction`; `Panel` takes `transition`, `keepMounted`.
- `Accordion` (`@funstack/ui/accordion`): `Root`, `Item` (`<details>`), `Trigger` (`<summary>`, first child of the Item), `Panel`. Without value props it needs no JavaScript; `exclusive` for one open item.
- `Collapsible` (`@funstack/ui/collapsible`): `Root` (the `<details>` itself), `Trigger` (`<summary>`, first child of the Root), `Panel`. One disclosure; use it rather than a lone `Accordion.Item`. `open` / `defaultOpen` / `openChangeAction` (no `onOpenChange`: find-in-page arrives as `reason: "platform"`); with none of them it needs no JavaScript, and `defaultOpen` alone (even `false`) selects library mode.
- `Tooltip` (`@funstack/ui/tooltip`): `Root`, `Trigger`, `Popup`, `Arrow`. Open state is the browser's (no open props); `delay`, `closeDelay`.
- `HoverCard` (`@funstack/ui/hover-card`): `Root`, `Trigger` (a link), `Popup` (render it right after the Trigger; `render={<span />}` inside running text). Opens on hover or keyboard focus after `delay` (600) as a request (`openChangeAction(true)`, content mounts in the transition and may suspend, Trigger `data-pending`); every close (lost interest after `closeDelay` 300, Escape, a press outside or on the link) is a fact for `onOpenChange(false)`. Content must be supplementary (nothing on touch); a click-to-open card is a Popover.
- `Popover` (`@funstack/ui/popover`): `Root`, `Trigger`, `Popup`, `Close`, `Title`, `Description`. `open` / `openChangeAction` (requests) / `onOpenChange` (dismissals); without open props it needs no JavaScript.
- `Dialog` (`@funstack/ui/dialog`): `Root`, `Trigger`, `Popup` (`<dialog>`), `Close`, `Form`, `Title`, `Description`. Same modes as Popover; `Dialog.Form` closes after its form action settles. A `Close` with `action` (Dialog or Popover) renders no native command, so it does nothing before hydration; the JS-free way to run work and close is `Dialog.Form` with a Server Function.
- `AlertDialog` (`@funstack/ui/alert-dialog`): a Dialog for confirmations. `Root` (no `modal`: always modal), `Trigger`, `Popup` (`<dialog role="alertdialog">`, no `lightDismiss`: a backdrop click does nothing), `Title`, `Description` (expected: dev warning without one), `Cancel` (focused on open; `initialFocus` on the Popup overrides), `Action`, `Form`. Put the confirmed work in `<AlertDialog.Action action={() => deleteProject(id)}>`: it pends on the button and closes the dialog when it resolves; a rejection keeps it open (place an Error Boundary inside the Popup to show it; a caught error resolves and closes). An Action with `action` does nothing before hydration (as every Close part with `action`); the confirm that works without JavaScript is `AlertDialog.Form action={serverFunction}` with a plain submit button. Escape always closes it (a fact for `onOpenChange`; no prop turns it off), and so does Cancel while the Action is pending (in library mode that close waits for the action to settle and shows nothing meanwhile: disable Cancel with your own `useOptimistic` flag set inside the action when the work is slow). Same transition types and data attributes as Dialog.
- `Menu` (`@funstack/ui/menu`): `Root`, `Trigger`, `Popup`, `Item` (`action`), `CheckboxItem`, `RadioGroup`, `RadioItem`, `Group`, `GroupLabel`, `Separator`, `SubmenuTrigger`, `ContextTrigger` (context menu). A `Root` inside a `Popup` is a submenu.
- `Toast` (`@funstack/ui/toast`): `toast()` (also `toast.promise`, `toast.update`, `toast.dismiss`), `createToastManager`, parts `Viewport`, `Root`, `Title`, `Description`, `Action`, `Close`.
- `Field` (`@funstack/ui/field`): `Root`, `Label`, `Control`, `Description`, `Error`. Native constraint validation, no validation engine. A textarea is `<Field.Control render={<textarea />} />`, grown with CSS `field-sizing: content` (no auto-size prop). `Field.Control` also works outside a `Field.Root` as the plain control (it takes `id` there; the other parts throw). There is no Input, Textarea or Fieldset part: use the native elements, and group Fields in a native `<fieldset>` / `<legend>` (`<fieldset disabled>` disables every FUNSTACK control inside, but their `data-disabled` does not see it: select `:disabled`). Never disable a fieldset because a submission is pending (focus is lost); use `form[data-pending]`.
- `Form` (`@funstack/ui/form`): `Root` (`action`, `errors` for server errors per field), `Submit`.
- `Checkbox` (`@funstack/ui/checkbox`): native checkbox; `checked` / `checkedChangeAction`, controlled-only `indeterminate`.
- `CheckboxGroup` (`@funstack/ui/checkbox-group`): `Root`, `Label`, `Item`, `Parent` (select-all). `value` is `string[]`.
- `RadioGroup` (`@funstack/ui/radio-group`): `Root`, `Label`, `Item`. Native radios; `value` / `valueChangeAction`.
- `Switch` (`@funstack/ui/switch`): native `<input type="checkbox" role="switch">`; `checked` / `checkedChangeAction`.
- `Select` (`@funstack/ui/select`): a real `<select>`. `Root`, `Trigger`, `Value`, `Option`, `Group`, `GroupLabel`, `Separator`. Styled picker via CSS `appearance: base-select`. Single value only: `<Select.Root multiple>` is a type error (dropped with a dev warning); use `MultiSelect`.
- `Combobox` (`@funstack/ui/combobox`): `Root`, `Label`, `Input`, `Trigger`, `Clear`, `Popup`, `List`, `Option`, `Group`, `GroupLabel`, `Empty`, `Status`, and with `multiple` `Chips`, `Chip`, `ChipRemove`. You render the options (no built-in filtering); `List` children get the deferred `query`; `inputValue` / `onInputValueChange` is urgent. `Root multiple`: `value` is `string[]` (pick order), `valueChangeAction(next, { added, removed })` (persist the diff); a pick toggles, clears the text and keeps the listbox open; render chips with `<Combobox.Chips>{({ value }) => value.map((v) => <Combobox.Chip key={v} value={v} />)}</Combobox.Chips>` next to the Input (not around it).
- `MultiSelect` (`@funstack/ui/multi-select`): a select-only combobox for several values (JS listbox on a popover; nothing opens before hydration). `Root`, `Label`, `Trigger` (`button[role=combobox]`, the Tab stop), `Value`, `Popup`, `List`, `Option`, `Group`, `GroupLabel`, `Empty`, `Status`. `value` is `string[]` (pick order), `valueChangeAction(next, { added, removed })` (persist the diff); a pick toggles and keeps the listbox open; full open-state API (`open`, `openChangeAction`, `onOpenChange`). Show the selection with `<MultiSelect.Value>{({ value }) => value.map((v) => names[v]).join(", ")}</MultiSelect.Value>` (the library knows a label only after the option was rendered once). `required` (at least one) blocks the submit with no browser bubble: put it in a `Field.Root` with `Field.Error` for the message. No chips, no search, no Clear: for those use `Combobox multiple`.
- `Slider` (`@funstack/ui/slider`): `Root`, `Label`, `Track`, `Indicator`, `Thumb`, `Value`. `valueChangeAction` per step, `valueCommitAction` once per gesture; `value` is a number or `number[]`.
- `NumberField` (`@funstack/ui/number-field`): `Root`, `Label`, `Input`, `Increment`, `Decrement`. Locale-formatted; `valueChangeAction`, `valueCommitAction`.
- `OTPField` (`@funstack/ui/otp-field`): `Root` (`length` required, `charset` `"numeric"` default / `"alphanumeric"` / `"alphabetic"`), `Input` (the one `<input autocomplete="one-time-code">`; name it with a `<label for>`, `Field.Label` or `aria-label`), `Slot` (`index` required; `aria-hidden`, `data-filled`, `data-active`). The text is urgent: `value` / `defaultValue` / `onValueChange(next, details)` (a fact, no transition). `completeAction(value, details)` runs in the Root's transition each time an edit leaves the code complete (`data-pending` on Root and Input; every completion runs, no `whilePending`; not at mount, reset or a controlled change); a wrong code is not an error: resolve and show a message, `setCode("")` to clear. `submitOnComplete` (default `false`) calls `requestSubmit()` on the Input's form (tell the user before the field; keep a submit button). `experimental_webOTP` asks for the SMS code (Chromium, Safari). Pasted `123 456` becomes `123456`; no `maxlength`; text typed before hydration is invisible until hydration (use the `@media (scripting: none)` recipe on the docs page for no-JS pages).
- `Progress` (`@funstack/ui/progress`) and `Meter` (`@funstack/ui/meter`): `Root`, `Track`, `Indicator`, `Label`, `Value`. Output only, no actions; the Root renders in a Server Component.
- `Separator` (`@funstack/ui/separator`): a single `<hr>`; `orientation` (`"horizontal"` default, `"vertical"`), `decorative` (`role="none"`, no `aria-orientation`: for a purely visual line; it is also the separator element that is valid inside a Combobox or MultiSelect listbox, where a Group boundary styled in CSS is the other option). `data-orientation` always; reset the `<hr>`'s margin and border in CSS. No `"use client"`: a Server Component may render it. Inside a Toolbar, Menu or Select use their own `Separator` part.
- `CSPProvider`, `STYLE_SHA256` (`@funstack/ui/csp`): for a strict `style-src` Content Security Policy.

## Full documentation

The full documentation (concepts, every component page with props tables, data attributes, keyboard behaviour and recipes) is bundled as Markdown in the installed package, matching its version. Start from the index, which ends with a list of all pages:

```
node_modules/@funstack/ui/dist/docs/index.md
```

Every other page is at `node_modules/@funstack/ui/dist/docs/<route>.md`, for example `components/dialog.md` or `concepts/action-props.md`.

If that file is missing (the package is not installed), use the online docs instead: https://ui.funstack.work/llms.txt lists every page, and each page is also available as Markdown at its URL plus `.md` (for example https://ui.funstack.work/components/dialog.md). The site documents the latest release.
